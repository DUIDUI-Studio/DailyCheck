# 企微库存助手 · 今晚交付计划

> 生成：2026-10-21 00:26
> 目标：今晚让内部员工在企业微信里用自然语言查库存、价格，拿到准确回复
> 已完成的前提验证：企微长连接收发双向打通、userid 明文、MiniMax function calling 可用

---

## 1. 结论先行

**能做，今晚可交付"可用版本"，但有一处数据事实必须先认。**

`items` 表里只有 `unit_cost`（成本均价），**没有售价字段**。所以员工问"价格"，能答的只有成本价。如果业务上需要区分售价和成本，今晚补不出来——那是数据模型的事，不是聊天层能解决的。

---

## 2. 架构：为什么不让机器人直接调 MCP

```
企业微信（员工自然语言提问）
        |
        v
长连接接入层  bot/serve.py      消息解码 / 会话上下文 / 流式回复
        |
        v
LLM 编排层    bot/agent.py      MiniMax-M3.1-Flash + function calling 循环
        |
        v  tool_calls（JSON Schema 定义，只读）
工具层        bot/tools.py      search_items / get_item_detail
                                list_low_stock / list_warehouses
        |
        v
数据层        SQLite（各仓 items 表，遍历 warehouses 表）
```

**不走 MCP 协议。** MCP 是给 Claude/Cursor 那类外部客户端协商用的；我们自己的进程直连 SQLite，少一跳序列化、少一个进程、少一处故障点。给 LLM 的工具定义本身就是 JSON Schema，和 MCP 的 `tools` 数组同构，只是不经过那套传输协议。

MCP 保留原用途：给外部 AI 客户端用。

## 3. 工具设计（4 个，全部只读）

| 工具 | 入参 | 返回 | 为什么要它 |
|---|---|---|---|
| `search_items` | `keyword` | 候选品项列表（含 sku/name/单位） | 员工不会说 SKU，会说"面粉""牛奶"。先模糊搜再定位，这是"答得准"的地基 |
| `get_item_detail` | `sku_or_name`, `warehouse_code?` | 各仓库存、安全库存、成本均价、单位、更新时间 | 主力工具，一次给全 |
| `list_low_stock` | `warehouse_code?` | 低于安全库存的品项，按缺口排序 | "哪些快断货了" |
| `list_warehouses` | 无 | 仓库编码 + 名称 | 让模型知道有哪些仓，避免瞎猜仓名 |

**关键约束：工具只返回结构化数据，不做任何自然语言加工。** 措辞交给模型，数字只能来自工具返回值。

---

## 4. 提问范围约束（写进 system prompt）

**允许**
- 某个品项还有多少、在哪个仓、够不够用
- 某个品项成本多少
- 哪些品项快断货、缺口多大
- 某个仓都有什么货
- 最近出入库情况（若后续扩工具）

**拒绝并说明**
- 下单、改库存、删除（本机器人只读）
- 财务报表、跨期对比、成本核算
- 与库存无关的闲聊（一句话带过，引导回库存）

**查不到时的强制行为**
- 先 `search_items` 找近似项，把候选念给用户："没找到'牛奶'，有'全脂牛奶粉''牛奶巧克力'，你要哪个"
- 仍然没有 → 直接说没有，不编造

---

## 5. 应答方式约束

| 约束 | 具体规则 |
|---|---|
| 数字来源 | 只能引用工具返回值，禁止模型自行计算或估计 |
| 零库存表述 | 说"已经缺货"，不要说"没有这个品项" |
| 多仓结果 | 用列表逐仓列出，标明仓名；总量单独一行 |
| 单位 | 必须带单位（件/箱/kg），不允许裸数字 |
| 价格口径 | 明确说"成本均价"，不要说"售价" |
| 长度 | 单条回复不超过 12 行，超了先给摘要再问要不要详情 |
| 不猜 | 仓名、SKU 不确定时先问，不自作主张 |

---

## 6. 自然流畅的三个关键点

**① 流式推送，把感知延迟压到 1 秒内**

长连接的 `stream` 类型支持分段推送。做法：
- 收到消息立刻推一条 `finish=False` 的"正在查…"
- 工具返回后，把答案按句子分批推
- 最后一条 `finish=True`

用户看到的是打字机效果，而不是等 4 秒后突然蹦出一大段。

**② 意图映射要宽**

同一句话有一堆说法，全部要能落到同一个工具：
`还有多少 / 剩几箱 / 库存多少 / 够不够 / 快没了吧 / 查一下 A001`

靠 tool description 写足同义词 + few-shot 示例，不靠正则。

**③ 兜底话术要具体**

听不懂时不要回"我不太明白"。给示例：
> 我可以查库存和成本，比如「面粉还有多少」「哪些快断货了」「上海仓有什么」
