# 生产耗料计量快照（GitHub #53）

生产提交在仓库 SQLite 的 `BEGIN IMMEDIATE` 内读取产出单位、配方及库存品计量，校验实际消耗，并一次性提交批次、耗料行、库存、自动出库和流水。录入页随表单发送包含仓库身份的计量依据指纹。若展示后切换仓库，或单位、原料、配方已变，服务端要求重开页面核对。旧表单或既有直接调用仍采用提交时的有效依据。手填零、覆盖量、空白代填及既有来源判定保持原口径。

批次保存产出单位。耗料行保存库存单位、本仓品项 ID、SKU、当时的可空 canonical ID、实际使用的配方行 ID 和每单位配方量。计算版本 1 先将产量与配方量的乘积舍入两位。克模式再除以当次每库存单位克数并舍入两位。库存单位模式直接以配方乘积入账，克重字段留空。仓库私有表 `production_item_measurement_revisions` 记录计量修订号。单位、SKU、绑定或克重变化时递增。删除品项后保留其修订号，重用同一 ID 时再次递增。普通 `items` 行保留原有结构。数据库拒绝更新已存快照。

`production_run_items.outbound_req_id` 在 v7 只有非唯一索引，旧行可能共享同一出库 ID。新写入为每条耗料生成独立出库 ID。出库读取校验全库唯一引用、品项、来源、批次、数量和同步回退状态后，引用同一快照。生产历史及 CSV 将缺失单位标为「单位未留存」。普通出库报告保留原流水汇总，含生产的单元格标注当前参考单位、旧行缺失及可能混用单位，逐笔单位见生产历史。MCP 只对同仓同品项的同计量身份聚合，并单列未知覆盖率。

回退与删除在库存写入前核对所有耗料与自动出库。当前库存单位、品项身份及计量修订号相符时，按历史入账量原数返库。当前主数据编辑没有留存库存余额重述证明，两个克重比例也无法证明合法返库量。遇到单位、身份或换算变化、历史单位未知及关联歧义，先核对库存证据。已唯一核实的零耗料可以返零。生产批次统一处理反向库存操作，Web 和 MCP 的普通出库反向入口拒绝生产出库。

## 发布与回退

- 候选先在独立数据库副本通过单仓 v7→v8。确认原记录数、库存余额、历史时间和旧行空值。检查可用磁盘空间、SQLite 热备的完整性和恢复结果。显式入口为 `python -m db.warehouse_migrate --db <warehouse> status|up`，Web 首次访问和迁移型 MCP 入口也按同一规则升级。策略只读 MCP 可直接读取 v7，并保持历史单位未知。
- v7 应用拒绝访问 `user_version=8` 的仓库。正式发布需先证明受支持的隔离切换可停止旧应用和后台仓库访问，迁移共享目标后仅将仓库流量交给 v8。以 Web 与 MCP 真实落点、库版本和生产领料读写烟测证明切换。按当前发布规则完成观察、合并与结算。现有版本的普通混跑流程需要 Peter 核对适用性。
- 软件回退先停止 v8 仓库访问和写入。在一致状态下保留当前 v8 热备，在同一共享库逐仓使用候选 CLI 的 `down --target 7` 回标，并验证 schema、快照和库存余额。旧进程在全部目标回标后恢复访问。普通库存操作可用，数据库会原子拒绝旧版生产回退及删除。旧程序显示原有单位口径，期间新增的生产行缺少快照。记录该窗口，恢复 v8 后验证这些行显示未知、已有快照保持原值。
- 初次升级使用正式 v7 或从 v7 制作的独立副本。#55 首版未发布。如果曾用首版候选生成带 `items.production_measurement_revision` 的私有预演库，请用其初始 v7 备份重建预演。已采用私有表的 v8 仓库走正常回标与恢复流程。
- SQLite 文件恢复用于已审核的数据恢复。预先在隔离路径校验迁移备份、`integrity_check` 和运行版本。恢复到写入前备份会丢失备份之后的合法业务交易，需要单独处理这些交易并经发布负责人授权。正常代码回退保留每条已落地业务记录和新快照。
