1. 需求速率：三口径融合，不只靠库存消耗

三路信号回答三个不同问题：领料/出库口径（高频、有偏）＝「账面扣了多少」； 产量口径（产量 × 标准单耗）＝「按生产量本来该用多少」； 盘点口径（期初实盘 + 入库 − 期末实盘，低频、无偏）＝「实际消失了多少」。 本期放行：盘点 {{ fuse_counts.get('count', 0) }} 项、领料 {{ fuse_counts.get('issue', 0) }} 项。

逐日序列仍取近 {{ params.window_days }} 天（含零消耗日）。连续消耗品项用 近远半段加权均值（{{ params.recent_weight | int }} : 1），间歇消耗品项用 Croston 分解（平均单次用量 ÷ 平均间隔天数）。

融合按「可信度优先」而不是加权平均：盘点定水平、领料定日形状 （按比例保形缩放，不是加常数）。三路偏差是系统性的 —— 损耗永远不进领料记录，领料速率只会偏低。对系统性偏差做加权平均， 只会得到一个稳定偏低的数，反而更危险。

2. 偏差识别：逐项校验

① 口径背离：同一品项 |领料速率 ÷ 盘点速率 − 1| > 10% 记漂移， 本期 {{ channels.drift_items }}/{{ channels.gap_items }} 项超线。 ② 数量级校验：盘点速率超领料速率 10 倍（或低于 1/10）判为录入异常， 整条盘点通道弃用并回退领料口径 —— 实测有一例「盘盈 +2208.35 / 次日盘亏 −2208.06」 的冲销对（净影响仅 +0.29 桶），夹在中间的区间会算出 2208 桶/天的消耗。 ③ 负消耗剔除：盘点区间算出负消耗（入库漏记/盘点错）整段丢弃， 不截断到 0，避免把「数据坏了」伪装成「没消耗」。

为什么不靠单区间跳变阈值：本数据集大量品项是间歇消耗，中位区间速率为 0， 按中位数倍数设阈值会把真实的大额领用一起删掉。跨口径数量级校验更稳。

3. 盘点校正：把「账面」换成「实盘」

C = I期初实盘 + 入库 − I期末实盘  ·  k = C ÷ 领料量

每周盘点给出真实水位，两期相减即为这段期间的真实消失量，完全不依赖领料记录。 k 是口径修正系数（品类级见上方对账表），没有盘点覆盖的品项用同品类 k 兜底，且 k 夹在 [0.5, 2.0] 之外一律不外推。

校正后的速率会同步放大 σ（保形缩放），否则只抬均值不抬波动，安全库存会被算小 —— 那正是「账面偏低 → 订得偏少 → 又断货」的闭环。

4. 为什么产量不能直接当需求

实测核对：production_run_items.actual_qty 与「生产消耗」动账 是同一本账 —— 逐品项集合完全一致、数量一致（差异来自回退）。 把它当「独立的第二信号」会重复计算同一份数据。真正独立的是 production_runs.output_qty（产量）：成品不做库存管理，生产即销售， 产量可以当销量代理。

用产量口径反而消除了「生产入库↔出库」的时滞：原料需求由产量驱动， 不由销量驱动 —— 成品什么时候卖掉，不影响原料什么时候该订。

5. 安全库存（周期盘点口径）

SS = z · σ日 · √(L + R)

σ日 为日消耗标准差；L 为到货提前期（DC {{ params.dc_lead_days }} 天 / 门店 {{ params.store_lead_days }} 天）；R 为订货复盘周期（{{ params.dc_review_days }} 天）。 z 按 ABC 分层：A {{ (params.service_a * 100) | round | int }}%、B {{ (params.service_b * 100) | round | int }}%、C {{ (params.service_c * 100) | round | int }}%。

为什么用 L+R 而不是 L：门店一周只能订一次货，库存水位每周才被修正一次， 风险敞口是「到货期 + 这一整周的复盘间隔」。用 √L 会把安全库存低估约 2.8 倍（L=1, R=7 时 √8/√1≈2.83），这正是「周订货制却按日补货算安全库存」 的典型错配。

6. 目标库存与订货量

S = d̄ · (L + R) + SS   ·   Q = max(0, S − 在手 − 在途)

即 (R, S) 定期订货、订至目标水位。在途包含已下单未收货的门店订单 与未到货的补货申请 —— 漏掉在途是重复下单的头号原因。 最后按最小包装向上取整。

为什么不用「再订货点 + 固定批量」：ROP 假设可以随时补货、每次订固定批量， 与「每周集中订一次」的实际流程不符。订至目标水位把「这一周会消耗多少」 一次性算进订单，避免周中反复补单。再订货点仍然可读：它就是 S 减去 d̄·R 的位置，表里的「可支撑天数 < L+R」等价于「已跌破再订货点」。

7. 经济订货批量（参考）

EOQ = √(2 · K · D年 / (h · 单价))

K = ¥{{ params.order_cost | fmt_money }}/单，h = {{ (params.holding_rate * 100) | round | int }}%/年。 本项目每周订货是业务硬约束，EOQ 不直接决定订货量， 只用来判断「这一单是否已经大到不经济」与「取整放大是否离谱」。

为什么只做参考：4 家门店的订单量由门店需求决定，拆单省下的持有成本 抵不过多跑一趟的固定成本；EOQ 真正的用处是暴露长尾品项按整桶/整箱 起订造成的过度备货（本期取整放大 ¥{{ kpi.round_up_value | fmt_money }}， 占建议额 {{ ((kpi.round_up_value / kpi.suggested_value * 100) if kpi.suggested_value else 0) | round | int }}%）。

8. DC 需求取「下游拉动」

DC 的日需求 = 该品项在全部门店的日消耗序列之和（按 canonical_id 对齐），只有 DC 独有品项才用本仓出库史。本期 {{ source_counts.get('downstream', 0) }} 个品项走拉动口径、{{ source_counts.get('own', 0) }} 个走本仓口径。

为什么：DC 是整周成批发货，直接用发货记录估日需求会得到巨大 σ。 实测同一品项用本仓出库史算出的安全库存是 107 袋（12 天用量）， 改用门店消耗汇总后降到合理量级 —— 批量的「峰」是可预测的，不该进安全库存。

9. 数据口径与已知缺口

消耗 = 生产消耗 + 出库（门店）／出库 + 门店订货出库 + 总仓调货出库（DC）， 并剔除 note 含「盘亏／盘盈／盘点」的盘点调整行。

为什么要剔除盘点：盘点盈亏是账实差异不是需求。生产数据里 新天地店的盘亏累计 2965、真实消耗仅 334，混在一起会让日均虚高近 10 倍 —— 旧版预测看板正是踩了这个坑。
